## Why this guard exists

`check_appointment_status` reads a patient's appointment record. Exactly one
agent needs that capability - the Lookup Agent, whose entire job is to fetch
one named record - so exactly one agent has it. Handing it to the Retrieval
Agent would let a policy question reach appointment data with no functional
gain, and handing it to the Composer would let the component that writes the
final wording also decide what data to fetch, which is precisely the
combination that turns a wrong retrieval into a confidently wrong answer.
The registry in `agents/governance.py` is the single authority; no other
module decides tool access, and `verify_registry_invariants()` additionally
asserts that the appointment tool has exactly one holder.
